# Auth API Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate login, registration, cookie-session guards, and auth-aware home CTAs against the Youthpreneur API contract.

**Architecture:** Keep HTTP transport in `src/lib/api/client.ts` and auth endpoint functions in `src/lib/api/auth.ts`. Keep Zod schemas in `src/schema/auth.ts`; pages own form state and navigation. Use `POST /auth/refresh` as the only session check because the backend uses HttpOnly cookies and exposes no current-user endpoint.

**Tech Stack:** React 19, TypeScript 6, React Router 8, Zod, Sonner, native `fetch`.

**Spec:** API contract `https://github.com/tnnz20/youthpreneur-be/blob/master/api/api-contract.md`, Authentication and User Endpoints sections.

## Global Constraints

- API base URL is `http://localhost:8080`.
- Auth uses cookie-based JWT; requests must use `credentials: 'include'`.
- Login endpoint is `POST /auth/login` with `{ email, password }`.
- Registration endpoint is `POST /users` with `{ email, password, full_name, nik?, birth_date?, gender?, district?, phone?, address? }`.
- Password length is 8–72 bytes; frontend may enforce 8–72 characters for practical validation.
- New users always receive the `member` role; never send a role from the client.
- Refresh endpoint is `POST /auth/refresh`; status `204` means authenticated.
- Validation and API failures use `toast.error(...)`; expected anonymous refresh failures stay silent.
- Preserve repository routing imports from `react-router`, existing Tailwind tokens, and no new comments.
- Run `npm run format:check`, `npm run lint`, `npm run typecheck`, and `npm run build`.
